============================================================
1. MAIN OBJECTIVE
============================================================

The goal of Milestone 12 is to allow the AI Research Assistant
to understand and summarize complete research papers using the
existing:

- PDF processing pipeline
- chunking system
- embeddings
- vector database
- semantic retrieval
- RAG pipeline
- LangGraph autonomous agent

evidence-grounded summaries of research papers.

The system must NOT simply send the entire PDF text to the LLM.

It should use an intelligent retrieval and summarization strategy
that can scale to long research papers.

============================================================
3. VERY IMPORTANT — AUTONOMOUS BEHAVIOR
============================================================

Do NOT implement the summarization workflow as a simple rule-based
system such as:

if "summary" in question:
    summarize()

Instead, use the existing LangGraph autonomous agent.

The agent should:

1. Understand the user request.
2. Determine the type of summary required.
3. Determine what evidence is necessary.
4. Decide which tools should be used.
5. Retrieve relevant evidence.
6. Determine whether more retrieval is necessary.
7. Synthesize the evidence.
8. Validate citations.
9. Produce the final response.

The agent should be able to decide whether it needs:

- abstract
- introduction
- methodology
- dataset
- experiments
- results
- discussion
- conclusion
- limitations
- contributions

depending on the user's request.

Do not force the agent to retrieve every section for every query.

7. LONG DOCUMENT HANDLING
============================================================

Do NOT send the entire document directly to the LLM.

Research papers may contain:

- thousands of words
- tens of thousands of tokens
- dozens of pages

Use a scalable strategy.

Possible approach:

MAP:

Group related chunks.

For example:

Group 1:
Chunks 1–5

Group 2:
Chunks 6–10

Group 3:
Chunks 11–15

Generate intermediate summaries:

Group 1 → Summary 1
Group 2 → Summary 2
Group 3 → Summary 3

Then:

REDUCE:

Summary 1
Summary 2
Summary 3

        ↓

Final LLM synthesis

        ↓

Complete summary

Use LangChain summarization utilities where they genuinely help,
but do not introduce abstractions that make the existing
architecture unnecessarily complex.

============================================================
14. MAP STAGE
============================================================

During the MAP stage:

For each chunk group:

1. Provide the LLM with relevant chunks.
2. Ask it to extract important information.
3. Preserve source identifiers.
4. Generate an intermediate summary.
5. Do not introduce unsupported claims.

Conceptual structure:

{
    "group_id": "group_01",
    "summary": "...",
    "sources": [
        "src_001",
        "src_002"
    ]
}

Do not lose source information.

============================================================
15. REDUCE STAGE
============================================================

The REDUCE stage receives intermediate summaries.

Example:

Summary 1
Summary 2
Summary 3
Summary 4

The LLM synthesizes them into a coherent final summary.

Important:

The final synthesis must remain grounded in the original evidence.

Do not treat intermediate summaries as authoritative sources.

Where possible, retain references to original source IDs.
