# Milestone 22 — Frontend Foundation

The goal of this milestone is to create the **complete frontend foundation** using **React + TypeScript** without yet implementing all advanced research features.

The frontend must be designed so that Milestones 23–25 can build on it without requiring a major rewrite.

---

# 1. First: Inspect the Existing Project

Before modifying anything:

1. Inspect the entire repository structure.
2. Identify:

   * Backend framework
   * Backend entry point
   * Existing API routes
   * Authentication endpoints
   * User/workspace endpoints
   * PDF/document endpoints
   * RAG endpoints
   * Database models
   * Existing environment variables
   * Docker configuration
   * Existing tests
   * Existing documentation
3. Understand the existing authentication mechanism.
4. Understand the API request/response formats.
5. Identify whether a frontend directory already exists.
6. Reuse existing project conventions wherever possible.

Do **not** rewrite or unnecessarily modify the working backend.

If the repository already contains partial frontend code, improve it instead of creating a duplicate frontend.

---

# 2. Frontend Technology Stack

Use:

* React
* TypeScript
* Vite
* React Router
* Axios or a clean fetch-based API client
* Modern CSS approach already used by the project; otherwise use a maintainable CSS architecture
* ESLint
* Prettier if already configured
* Lucide React or another lightweight icon library if needed

Do not introduce unnecessary libraries.

Prefer simple, maintainable architecture over excessive dependencies.

# 7. Authentication State

Implement a clean authentication state system.

The frontend should know:

```text
authenticated
unauthenticated
loading
```

Create an appropriate authentication context/provider or state solution.

It should support:

* Login
* Logout
* Persisting authentication state
* Getting current user
* Protected routes
* Redirecting unauthenticated users
* Redirecting authenticated users away from login/register when appropriate

If the backend uses JWT:

* Store tokens securely according to the project's architecture.
* Attach the access token to protected API requests.
* Handle expired/invalid tokens.
* Automatically clear authentication state when the backend returns an authentication failure.

Do not expose secrets in frontend code.

# 8. Protected Route

Create a reusable protected route mechanism.

Example behavior:

```text
User opens /dashboard
        ↓
Is authenticated?
   ┌────┴────┐
   │         │
  YES       NO
   │         │
   ▼         ▼
Dashboard   /login
```

While authentication status is being determined, show a loading state rather than incorrectly redirecting the user.

# 22. Frontend Security

Follow basic security practices:

* Never hardcode API keys
* Never commit secrets
* Validate uploaded files
* Do not trust client-side validation alone
* Avoid unsafe HTML rendering
* Do not use `dangerouslySetInnerHTML` unless absolutely necessary
* Handle authentication failures correctly
* Do not expose internal backend information

Remember that frontend validation is only a UX feature; backend validation remains authoritative.
